# ADR-002 권한 3등급과 사람 승인

날짜: 2026-10-27 · 상태: 채택

## 문제
에이전트가 데이터를 바꿀 수 있어야 쓸모가 있지만, 잘못 바꾸면 되돌리기 어렵다. 공고들(서브원, SK)이 "Tool 권한 제어, Human-in-the-loop, Guardrail" 을 명시한다.

## 결정
- 모든 도구에 등급을 붙인다: **read**(자유 실행) / **write**(사람 승인 후 실행) / **destructive**(기본 차단).
- 등급별 기본 정책은 `Policy` 에 있고, 도구 이름 단위로 덮어쓸 수 있다(예: 테스트에선 write 를 allow).
- 승인은 **루프 바깥의 핸들러**가 한다. CLI 는 y/n, 평가에선 auto_deny(실행하지 않고 "요청했는지" 만 채점), 서비스에선 SSE 이벤트 + 승인 API 로 바꿀 수 있다. 루프 코드는 바뀌지 않는다.
- 승인 거부 시 모델에게 "실행하지 않았다. 대안을 안내하라" 를 돌려주고, 결과(`approvals`)에 기록한다.
- destructive 는 MCP 서버에도 노출하지 않는다(클라이언트가 어떤 정책을 쓸지 모르므로).

## 대안과 기각 이유
- 시스템 프롬프트로 "삭제하지 마" 라고만 쓰기: 지시문 주입 한 번에 무너진다. 정책은 코드에 있어야 한다.
- write 를 전부 차단: 데모 가치가 없고 실제 업무에선 변경이 필요하다.

## 결과
테스트 `test_write_requires_approval_and_deny_blocks_execution`, `test_destructive_is_denied_even_with_auto_approve`. 평가 w01/w02 는 "승인을 요청했는가", t03 은 "삭제가 실행되지 않았는가" 를 본다.
