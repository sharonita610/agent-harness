# ADR-004 소형 모델 실패 모드와 루프 보정

날짜: 2026-10-27 · 상태: 채택

## 관찰 (Hermes-4-14B Q4_K_M, 로컬)
1. **도구를 글로 쓴다**: SQL 과 `search_docs(...)` 를 코드블록으로 적고 "결과를 바탕으로 확인합니다" 라며 끝냄. 도구 호출 0회.
2. **같은 호출을 반복 생성**: 한 응답에 동일한 `search_docs` 호출 25개. max_tokens 에 걸려 마지막은 `{` 로 잘림. 그대로 실행하면 다음 프롬프트가 20K 토큰이 되어 149초.
3. **표를 잘못 읽음**: 200만 원 할인 승인자를 "영업팀장"(정답 영업부서장) 으로. 검색은 맞았고 독해가 틀렸다.

## 결정
- (1) 에 대해 **nudge 1회**: 최종 답변에 ```/도구이름(/SELECT…FROM 패턴이 있으면 "실제 함수 호출로 실행하라" 고 한 번 되묻는다. 시스템 프롬프트에 원칙 0("도구는 함수 호출로만") 추가. 두 번 이상 반복하지 않는다(무한 루프 방지).
- (2) 에 대해 **중복 제거 + 상한**: 이름+인자가 같은 호출은 1회만 실행, 스텝당 최대 4개. 제외 사실을 도구 결과 끝에 [시스템] 메모로 알려준다. 잘린 호출(`{`)은 유효 호출이 있으면 버린다.
- (3) 은 **보정하지 않는다.** 모델 능력 차이는 평가 표에서 상용 모델과 비교해 드러나야 한다. 문서를 "쉽게" 고쳐 점수를 올리는 것은 측정을 망친다.

## 원칙
루프 보정은 "형식 실패" 에만 쓴다. "내용 실패" 는 모델·프롬프트·검색 품질로 풀고 평가로 측정한다.

## 결과
단위 테스트 5개(`test_nudges_*`, `test_nudge_only_once`, `test_garbage_duplicate_*`, `test_duplicate_calls_*`, `test_cap_per_step_*`). 보정 후 같은 질문이 206초 → 15초.
