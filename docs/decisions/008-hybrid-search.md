# ADR-008 문서 검색: BM25 + 임베딩 하이브리드(RRF), 없으면 BM25

날짜: 2026-10-28 · 상태: 채택

## 문제
규정 문서 검색이 틀리면 에이전트가 자신 있게 틀린다(Hermes-4 의 m02). 한국어 BM25 는 조사·동의어에 약하다("환불은 언제 되나" 가 반품 규정을 못 찾음). 임베딩 서버는 있을 수도 없을 수도 있다.

## 결정
- **두 순위를 RRF 로 합친다.** `score = Σ 1/(60 + rank)`. 점수 스케일이 다른 BM25 와 코사인을 정규화 없이 섞을 수 있고 파라미터가 하나다.
- **임베딩은 OpenAI 호환 `/v1/embeddings`** 로만 부른다. 로컬은 llama-server + embeddinggemma-300m(768차원, 300MB, 8082), 상용은 같은 코드로 OpenAI 임베딩.
- **서버가 없으면 BM25 만.** 시작 시 `/health` 로 감지, `HARNESS_HYBRID=0` 으로 강제 off. 결과 형식은 동일하고 `mode` 필드로 어느 쪽인지 남긴다.
- **벡터는 청크 해시로 캐시**(`data/doc_embeddings.json`). 문서가 안 바뀌면 재계산 없음.
- **검색 품질은 따로 잰다.** `harness retrieval-eval`: 질문 18개 → 기대 문서, hit@1 / hit@3 / MRR 을 모드별로.

## 측정 (2026-10-28, embeddinggemma-300m, 문서 10개 · 청크 40개)
| 모드 | hit@1 | hit@3 | MRR |
|---|---|---|---|
| bm25 | 89% | 94% | 0.91 |
| vector | 100% | 100% | 1.00 |
| hybrid | 94% | 100% | 0.97 |

해석: 이 규모에선 벡터 단독이 가장 좋았고, 하이브리드는 BM25 의 오답 1위("거래처 등급" → 할인 규정)에 끌려 1건을 놓쳤다. 그래도 hit@3 는 100% 라 에이전트가 k=3~5 로 읽으면 차이가 없다. 문서가 수백 개로 늘면 BM25 의 정확 일치(코드·숫자·고유명사)가 다시 중요해지므로 하이브리드를 기본으로 둔다. 질문 18개는 작은 표본이다.

## 다음
리랭커(cross-encoder) 추가, 청크 단위 조정(절 → 문단), 표본 50개 이상으로 재측정.

## 추가 (2026-10-28): 호스팅 임베딩과 비교
같은 18문항을 OpenAI `text-embedding-3-small` 로 돌리면 vector 100% / hybrid 100%(로컬 embeddinggemma-300m 은 100% / 94%). 로컬 하이브리드가 놓친 1문항은 BM25 의 오답(단어 겹침이 많은 다른 규정)이 RRF 에서 벡터의 정답을 근소하게 이긴 경우였고, 호스팅 임베딩은 벡터 순위 차가 커서 복구됐다. 결론은 같다: 벡터가 강한 곳에서는 하이브리드의 이득이 작거나 음수일 수 있으니, 융합 가중(또는 BM25 점수 하한)은 검색 평가로 정해야 한다. 임베더는 환경변수 두 개로 교체되며 캐시 키에 모델명이 들어가 섞이지 않는다.
