# ADR-009 화면 디자인: 장부 종이와 먹, 결재 전표

날짜: 2026-10-28 · 상태: 채택

## 문제
첫 React 화면은 "둥근 카드 + 회색 그림자 + 보라 강조 + 가운뎃점 나열" 이었다. 어느 프로젝트에나 나오는 기본값이고, 에이전트가 한 일이 JSON 로그처럼 보여 읽기 피곤했다.

## 결정
- **주제에서 시각 언어를 가져온다.** 한국 도매회사 운영팀의 장부·전표·결재 도장. 종이 `#F3F5F7`, 먹 `#1B2430`, 괘선 `#D7DDE3`, 행동색 청록 `#0E6B63`, 도장 빨강 `#C8362B`(결재 도장과 반려·오류에만).
- **글꼴 한 가족.** Pretendard(한글 UI 가독성). 본문 15px / 줄높이 1.6, 표 숫자 폭. 코드·JSON 만 고정폭.
- **기억에 남는 요소는 하나.** 결재 전표: 왼쪽 빨간 여백선이 있는 전표에 인자를 표로 적고, 승인하면 빨간 "승인" 도장이, 반려하면 회색 "반려" 도장이 찍힌다(사용자 동작에만 반응하는 유일한 모션, reduced-motion 존중).
- **에이전트가 한 일은 타임라인으로.** 괘선 하나에 점을 찍어 "데이터 조회 → 결과 → 결재 대기 → 승인됨 → 결과" 를 사람 말로 보여주고, SQL·JSON 원문은 접어 둔다. 도구 이름은 한국어 라벨로 바꾼다(run_sql → 데이터 조회).
- **조용한 크롬.** 카드 격자 대신 여백과 괘선, 그림자 없음, 대문자 라벨·가운뎃점 나열·화살표 버튼 없음. 상태는 문장으로("결재 대기 1건").
- **쓰는 말.** 버튼은 일어날 일을 그대로("승인하고 실행", "반려", "맡기기"), 빈 화면은 다음 행동을 안내, 오류는 원인과 조치.

## 기본값 점검에서 바꾼 것
크림 종이+세리프+테라코타, 검정+형광, 카드 키트, 눈썹 라벨, 가운뎃점 메타 문자열을 전부 피했다. 숫자 번호(01/02)는 단계가 아니라 쓰지 않는다.

## 함께 고친 것
- 서버가 죽을 때 running/queued 로 남은 실행과 pending 결재를 시작 시 정리(`Store.fail_stale`). 재시작 뒤 "실행 중" 유령 항목이 남던 문제.
