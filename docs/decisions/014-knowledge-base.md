# ADR-014 지식 베이스: 765쪽 매뉴얼을 절 단위로 잘라 SQLite 에, 임베딩은 증분으로

날짜: 2026-10-28 · 상태: 채택

## 문제
회로 팩의 `search_manual` 은 직접 쓴 요약 문서 6개(37청크)만 봤다. 공고가 묻는 "도메인 문서 지식 베이스와 검색 파이프라인" 은 수백 쪽짜리 실제 문서를 넣고, 잘라서, 두 색인으로, 도구로 노출하고, 숫자로 재는 것이다. ngspice 공식 매뉴얼(PDF 765쪽, 책갈피 840개)을 넣기로 했다.

## 결정
1. **청킹 경계는 책갈피(TOC)의 절 번호.** 고정 길이로 자르면 명령 설명과 파라미터 표가 중간에 끊긴다. 책갈피의 "2.1.1 Input file structure" 를 본문 블록에서 찾아 경계로 쓰고, 머리글(절 제목 + 쪽번호)과 바닥 쪽번호는 위치(y)로 버린다. 긴 절은 문단 경계에서 1,800자 안쪽으로 나누되 같은 절 번호를 유지한다. 결과: 절 786개 → 청크 1,137개(중간 940자), 0.7초.
2. **저장은 SQLite 한 파일.** `chunks`(절 번호·제목 경로·쪽) + FTS5(BM25) + `embeddings(hash, model, vec)`. 메모리 색인(DocIndex)과 같은 `search / list_docs / mode` 인터페이스라 도구 코드는 바뀌지 않는다.
3. **임베딩은 (모델, 청크 해시) 단위로 증분.** 문서를 다시 넣어도 내용이 같은 청크는 다시 계산하지 않고, 로컬(embeddinggemma 768차원)과 호스팅(text-embedding-3-small 1536차원)을 같은 파일에 나란히 둔다. 벡터 검색은 numpy 행렬 곱(1,174 × 1,536, 수 ms).
4. **검색 → 읽기 두 도구.** `search_manual` 은 청크 앞 600자만 돌려주고(5건이면 3천 자, 컨텍스트 예산 안), `read_manual(section_id)` 로 절 전체(최대 4,000자)를 읽는다. 출처는 "ngspice manual > 11.3.10 .TRAN (p.337)" 형식.
5. **평가 세트는 절 번호로.** 32문항에 정답 절(번호, `11.4*` 같은 접두, 또는 요약 문서 출처 조각)을 적었다. 한국어 질문 → 영어 매뉴얼, 영어 키워드 질문, 요약 문서에만 있는 한국어 설명을 섞어 BM25 와 임베딩의 강약이 드러나게 했다.

## 결과 (hit@1, 32문항)
| 색인 | BM25 | 벡터 | 하이브리드 |
|---|---|---|---|
| 요약 문서 6개만 | 44% | 44~47% | 41~44% |
| 매뉴얼 + 요약 (로컬 embeddinggemma) | 84% | 69% | 81% |
| 매뉴얼 + 요약 (OpenAI text-embedding-3-small) | 84% | 81% | **97%** |

- 지식 베이스가 적중률을 두 배로 올렸다(44 → 84~97%). 요약 문서만으로는 인덕터·커패시터·.FOUR 같은 주제가 아예 없었다.
- **하이브리드가 항상 낫지 않다.** 로컬 임베딩은 영어 기술 문서 + 한국어 질문에서 벡터 69% 에 그쳤고, 융합해도 BM25 단독(84%)보다 낮았다. 호스팅 임베딩은 벡터 81% 로 올라가며 융합이 97% 가 됐다. 융합의 이득은 두 신호가 서로 다른 문항을 맞힐 때만 생긴다.
- 남은 오답은 대부분 "이웃 절" 이다(.meas 질문에 11.4.5 Trig Targ, MOSFET 질문에 7.6.2 모델). 평가 세트에 접두 매칭(`11.4*`)을 넣어 이런 경우를 정답으로 인정했고, 그 판단 기준을 yaml 주석에 남겼다.

## 대안과 기각 이유
- 벡터 DB(Chroma, LanceDB): 1천~1만 청크에는 과하다. SQLite 파일 하나가 배포·백업·테스트에 단순하다. 10만 청크를 넘기면 그때 바꾼다.
- 고정 길이 청킹 + 겹침: 표와 명령 설명이 끊긴다. 절 경계가 있는 문서에서는 구조를 쓰는 것이 낫다.
- PDF → 마크다운 변환기(pymupdf4llm): 품질은 좋지만 절 번호 복원이 불안정했다. 책갈피 + 블록 위치가 더 단순하고 재현된다.

## 한계
리랭커 없음, 표는 텍스트로만(열 정렬 깨짐), 한국어 조사 처리는 접두 검색, 매뉴얼 한 권. 다음 단계는 반도체 소자 라이브러리(표 데이터 → 정확 조회 도구)와 모델 카드 문서를 같은 지식 베이스에 넣는 것.
