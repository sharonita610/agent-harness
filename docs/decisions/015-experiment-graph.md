# ADR-015 실험 추적 그래프: 실행을 회로·소자·측정의 관계로 기록한다

날짜: 2026-10-28 · 상태: 채택

## 문제
시뮬레이션 비서를 쓰다 보면 "지난번 R1 을 2.2 kΩ 로 했을 때 차단 주파수 얼마였지", "같은 회로로 돌린 실행 전부 보여줘", "이 두 실행은 뭐가 달라" 같은 질문이 나온다. 파형 파일과 로그만으로는 답할 수 없다. 실행 사이의 *관계*(같은 토폴로지인가, 어떤 값이 다른가, 어떤 측정이 나왔나)를 저장해야 한다. 공고의 "KG(지식 그래프)" 와 알세미 공고 분석의 "과거 실행 결과 검색" 이 이 지점이다.

## 결정
1. **그래프는 SQLite 두 테이블.** `nodes(id, type, label, props)` + `edges(src, rel, dst, props)`. 노드 다섯 종류(circuit · component · analysis · run · measurement), 관계 일곱 가지(simulates, has_component, has_analysis, measured, has_point, varies, variant_of). 그래프 DB 는 수천 실행 규모에서 과하다. 질의는 파이썬 쪽 필터로 충분하다.
2. **회로는 본문 해시로 중복 제거, 토폴로지는 값을 뺀 해시.** 같은 넷리스트는 같은 회로 노드를 쓰고, 소자 이름·종류·노드가 같고 값만 다른 회로는 `variant_of` 로 양방향 연결하며 **값 차이(diff)를 관계에 적는다**. "R1 1k → 2.2k" 가 그래프의 지식이다.
3. **기록은 도구 안에서 자동.** `run_simulation` 과 `run_sweep` 이 결과를 돌려주기 전에 그래프에 넣는다. 스윕은 점마다 `sweep_point` 실행으로 펼쳐서 "R1=4.7k 일 때 fc" 가 스윕에서 나온 값이어도 찾히게 한다.
4. **질의 도구 세 개.** `query_history`(소자 값 ±1%, 측정값 범위, 제목), `compare_runs`(소자 차이·측정값 비율), `circuit_family`(같은 토폴로지 변형과 그 실행·측정). 프롬프트는 "과거 실행 질문은 다시 시뮬레이션하지 말고 기록 도구 값을 쓴다" 로 못 박았다(처음엔 "숫자는 반드시 run_simulation" 규칙과 충돌해 모델이 기록을 찾고도 재실행했다).
5. **평가는 시드 위에서.** `harness seed --pack spice` 가 그래프를 비우고 기준 실행 5개(RC R1=470/1k/2.2k/4.7k, 계단 응답)를 실제로 돌려 넣는다. 기록 문제 4개(h01~h04)는 그 상태에서 출발한다. 정답은 여전히 공식이다.

## 결과
- 로컬 gpt-oss-20b, 기록 문제 4개 n=1: 프롬프트 충돌 수정 후 전부 통과. 특히 h03 은 `run_simulation` → `circuit_family(run_id)` 로 같은 토폴로지 실행 5개를 R1·fc 표로 돌려줬고, h02 는 두 번 시뮬레이션한 뒤 `compare_runs` 로 "R1 1k→3.3k, fc 비율 0.303" 을 인용했다.
- `harness graph svg` 가 회로 → 실행 → 측정 3층 그림을 만든다(변형 관계는 값 차이가 가장 작은 쌍만 잇는 최소 신장 트리로 그려 엉킴을 막았다). README 에 넣었다.

## 대안과 기각 이유
- 실행 로그 전문 검색(지식 베이스에 넣기): "뭐가 다른가" 를 글 유사도로는 못 잰다. 값 차이는 구조로 저장해야 한다.
- Neo4j 등 그래프 DB: 배포·테스트 비용이 크고 이 규모에선 이득이 없다. 스키마는 노드/관계 표준형이라 나중에 옮길 수 있다.
- 매뉴얼에서 뽑은 문서 그래프(명령·파라미터·오류 관계): 다음 과제. 검색이 이미 97% 라 이득 측정이 목적이다.

## 한계
그래프는 팩 단위 한 파일이고 사용자별 분리가 없다. 변형 판정은 소자 이름이 같아야 하므로 이름을 바꿔 쓰면 다른 토폴로지로 본다. 측정 이름은 자유 문자열이라 "fc" 와 "f_c" 는 다른 측정이다.
