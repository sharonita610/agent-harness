# ADR-019 비서를 거치지 않는 길: 결재함·맡긴 작업·기록·데이터 탭

날짜: 2026-10-29 · 상태: 채택

## 문제
ADR-018 의 업무 데스크는 "비서에게 묻는 창" 하나에 결재함·작업·기록이 오른쪽에 곁다리로 붙어 있었다. 실무자가 실제로 쓴다고 보면 두 가지가 빠져 있었다.
1. **비서 없이 상태를 보는 길.** 결재가 몇 건 밀렸는지, 맡긴 집계가 끝났는지, 어제 무엇을 물었는지는 질문할 일이 아니라 들여다볼 일이다.
2. **답을 원 데이터와 대조하는 길.** 비서가 "2라인 권취가 5배 튀었다" 고 하면 사람은 그 숫자를 표나 그래프에서 확인하고 싶다. 근거 카드는 도구가 돌려준 조각일 뿐 전체 그림이 아니다.

## 결정
1. **보기 다섯 개.** 사이드바에 작업지 · 결재함 · 맡긴 작업 · 기록 · 데이터. URL(`?view=`)에 남아 공유·새로고침이 된다. 오른쪽 레일은 작업지에서만 요약으로 남는다.
2. **데이터 탭은 팩이 공급한다.** `Pack.dashboard(scope) -> [패널]`, 패널 종류는 여섯 가지(`stats` 숫자 타일, `table`, `line`, `bar`, `heat` 격자, `image`)로 고정하고 서비스가 `GET /dashboard` 에서 모양을 검사한다(`check_panels`). 플랫폼은 팩이 무엇을 보여 주는지 모르고 모양만 그린다. 팩마다 화면 코드를 쓰지 않는다는 ADR-018 의 원칙을 데이터에도 적용한 것이다. 사용자 데이터 범위(scope)는 비서와 같은 임시 뷰로 걸린다: 부산 담당자는 데이터 탭에서도 부산 주문만 본다.
3. **네 팩의 패널.** 회사: 주문 상태·월별 지연·지연 사유·안전재고 미달·최근 지연 주문. 공정: 최근 2주 라인×공정 NG율 격자, 일별 NG율 선, 급증 구간(비서의 `detect_spikes` 와 같은 규칙: 중앙값의 3배), 불량 유형, 조치 티켓. 회로: 회로 목록, 해석 종류, 최근 실행과 측정값, 실험 추적 그래프 그림. 총괄: 비서별 연결·도구·모델·대기 결재.
4. **그래프는 직접 그린다.** 라이브러리 없이 SVG. 축 하나, 얇은 마크, 계열 색은 이름이 아니라 자리로 고정(청록·파랑·주황·보라), 둘 이상이면 범례와 끝 라벨, 호버하면 그 x 의 값 전부, "표로 보기" 로 같은 데이터를 표로. 격자는 한 색조의 농도만 쓰고 숫자를 항상 글로도 적는다.
5. **기록은 작업지로 되살린다.** 기록·맡긴 작업에서 고른 실행을 저장된 이벤트와 결재로 작업지 한 장으로 다시 그린다(ADR-018 의 "새로고침하면 작업지가 사라진다" 한계 해소). 트레이스는 여전히 "실행 상세" 드로어.
6. **근거 카드에서 데이터로.** 작업지의 근거 카드마다 "데이터 보기" 가 있어 답 → 원 데이터로 한 번에 건너뛴다.

## 결과
- 공정 비서의 "어디서 언제 튀었나" 답(2라인 권취 10-18 09~14시, 4.6배)을 데이터 탭의 급증 구간 표 첫 줄에서 같은 숫자로 확인할 수 있다. 심어 둔 이상 세 개(A·B·C)가 전부 표에 보인다.
- 결재자는 결재함 탭 하나로 네 비서의 대기 전표와 처리 내역(누가 언제 승인·반려)을 본다.
- 테스트 5개: 패널 규약, 범위 적용(부산 < 전체), 심은 이상이 1위, 빈 실행 폴더, 끊긴 비서 표시, 엔드포인트.

## 대안과 기각 이유
- **Grafana·Metabase 를 옆에 띄우기.** 설치 부담이 크고, 사용자별 데이터 범위를 두 곳에서 따로 맞춰야 한다. 포트폴리오 심사자가 바로 볼 수도 없다.
- **차트 라이브러리.** 번들이 커지고 네 종류 그래프에 과하다. 직접 그린 쪽이 디자인 규칙(한 축, 고정 색 순서, 표 대체)을 지키기 쉽다.
- **데이터 탭을 비서에게 물어서 채우기.** 느리고 비결정적이다. 데이터 탭의 존재 이유가 "비서 없이" 다.

## 한계
- 패널 종류 여섯 가지로 못 그리는 것(산점도, 지도)은 팩이 그림(`image`)으로 만들어야 한다.
- 표는 20행까지만 보여 준다. 더 보려면 비서에게 묻거나 API.
- 데이터 탭은 30초 폴링이고 필터가 없다(기간·라인 고정). 기간 선택은 다음 차례.
