# ADR-022 소자 라이브러리: 모델 카드를 팩 안에 두고 넷리스트에 자동으로 붙인다

날짜: 2026-10-29 · 상태: 채택

## 문제
회로 팩은 R·L·C 와 이상 전원만으로 된 회로를 돌렸다. 실무 질문은 "1N4148 에 1mA 흘리면 몇 V 떨어지나", "2N2222 로 만든 스위치가 켜지나" 처럼 **실제 소자**를 부르는데, 모델 카드(`.model`)를 모델(LLM)이 외워 쓰면 수치가 틀리거나 형식이 깨지고, 파일 포함(`.include`)은 가드가 막는다(ADR-013).

## 결정
1. **팩 안의 작은 라이브러리.** `harness/packs/spice/library/parts.json` 에 다이오드 4, BJT 4, MOSFET 2, 연산증폭기 1. 교과서식 근사 모델이며 제조사 모델이 아니라는 안내를 데이터와 도구 응답에 함께 둔다.
2. **도구 둘.** `search_parts(query, kind)` 와 `get_part(name)`. 결과에는 모델 카드와 연결 예시(`D1 anode cathode D1N4148`)가 들어 있어 모델이 소자 줄을 틀리게 쓰지 않는다.
3. **자동 부착.** `run_simulation`·`run_sweep` 의 `parts=[...]` 에 이름을 주면 모델 카드가 넷리스트 끝(.end 앞)에 붙는다. 같은 이름은 한 번만. 넷리스트에 **같은 이름의 한 줄 `.model`** 이 이미 있으면 라이브러리 카드로 바꾼다(요청한 쪽이 이긴다. 첫 평가에서 모델이 `.model 1N4148 D` 처럼 기본값 다이오드를 직접 적고 parts 도 주는 바람에 건너뛰어 0.655 V 가 나왔다). `.subckt` 는 여러 줄이라 건너뛰고 응답의 `parts_applied` 에 적는다. 같은 평가에서 본 습관 둘도 여기서 흡수한다: 소자 줄에 model 이름(`D1N4148`) 대신 부품 이름(`1N4148`)을 쓰면 바꿔 주고, 제너를 `Z1 …`(SPICE 에선 MESFET), 연산증폭기를 `U1 …` 처럼 종류에 안 맞는 첫 글자로 쓰면 맞는 글자를 앞에 붙인다(`Z1` → `DZ1`). 전부 `parts_applied` 에 남는다. 넷리스트 가드는 그대로다: `.model`·`.subckt` 만 들어가고 파일 포함은 여전히 없다.
4. **정답은 같은 모델로 미리 돌려 고정.** 라이브러리 태스크(`tasks_spice_library.yaml`)의 정답은 라이브러리 모델 카드로 ngspice 를 직접 돌린 값이고, 테스트가 그 값을 고정한다. 모델이 다른 모델 카드를 외워 쓰면 틀리게 되어 있다.

## 결과
- 도구 15 → 17. 데이터 탭에 라이브러리 표 패널. 문서 `07-소자-라이브러리.md` 가 매뉴얼 검색에도 들어간다.
- 평가: 라이브러리 태스크 4개(Vf, 제너 안정화, NPN 목록, Bf 조회) × n=3, 로컬 gpt-oss-20b. 75%(처음) → 75%(`.op` 파서 수정 후) → 83%(소자 줄 자동 수정·단락 경고 후, 10/12). 문서형 2문항은 9/9, 시뮬레이션형 2문항은 8/12 → 4/6. 세 번의 실행이 찾아낸 것은 전부 도구 결함이었고(`.op` 숫자 노드 전압 누락, 같은 이름 `.model` 건너뜀, 부품 이름·소자 글자 습관), 남은 실패 2건은 전류원 방향과 직접 쓴 제너 모델이라는 모델의 회로 실수다. README 의 회로 평가 절에 과정이 있다.

## 대안과 기각 이유
- **`.include` 를 라이브러리 폴더에 한해 허용.** 가드에 예외가 생기고, 경로 처리가 공격면이 된다. 이름 → 카드 치환이 더 작고 안전하다.
- **제조사 모델 파일 수록.** 라이선스가 제각각이라 공개 레포에 넣을 수 없다. 근사 모델임을 밝히는 쪽을 택했다.
