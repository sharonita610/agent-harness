# ADR-023 규정 문서 그래프: "이 문서를 바꾸면 같이 봐야 하는 문서"

날짜: 2026-10-29 · 상태: 채택

## 배경

회사 팩의 규정 문서 10개는 서로를 인용한다. 재고 부족 처리 절차는 "주문 취소 규정에 따라 처리한다" 고 적고, 주문 취소 규정은 "보상 규정 CS-002 참조" 라고 적는다. 검색(`search_docs`)은 질문과 닮은 절을 찾아 주지만 "배송 지연 보상 규정을 개정하면 어떤 문서를 같이 손봐야 하나" 는 문서 **사이**의 관계 질문이라 검색으로는 답이 안 나온다. 실제 규정 관리에서 가장 흔한 질문 중 하나다.

## 결정

문서 폴더에서 그래프를 자동으로 만들고(`harness/retrieval/docgraph.py`) 도구 두 개로 묻는다.

- 노드: 문서(문서번호·제목·담당·개정일·절 목록). 머리 `문서번호: XXX-000` 와 `## 절` 구조만 있으면 어느 팩이든 쓴다.
- 간선 세 종류
  - **참조**(방향 있음): 본문이 다른 문서의 번호(`CS-002`), 제목, 짧은 제목("보상 규정", "반품 규정")을 적음. 짧은 제목은 제목에서 규칙으로 만든다("배송 지연 보상 규정" → "배송 지연 보상", "보상 규정"; "반품 및 교환 규정" → "반품 규정", "교환 규정").
  - **주제**(방향 있음): 본문이 다른 문서의 절 제목을 그대로 씀(거래처 등급 기준의 표 머리 "기본 할인" → 할인 승인 규정의 절). 라벨에 절 이름.
  - **데이터**(방향 없음): 같은 데이터 개념을 다룸. 문서는 DB 열 이름을 거의 안 쓰고 "안전재고", "지연 사유" 같은 업무 용어를 쓰므로, 팩이 **개념 사전**(개념 → DB 위치, 본문 표현들)을 준다. 회사 팩은 12개(안전재고 = `inventory.safety_stock`, 지연 사유 = `orders.delay_reason` …).
- 도구
  - `related_docs(name)`: 인용함·인용됨·같은 데이터 문서와 이 문서의 데이터 개념.
  - `impact_of(name)`: 이 문서를 인용하는 문서를 2단계까지(`impacted`, 거친 문서를 적음) + 같은 데이터 개념 문서(`shares_data`, 1단계). 인용 사슬과 데이터 공유를 섞지 않고 따로 돌려줘 비서가 "직접 인용 2건, 같은 데이터 3건" 처럼 말할 수 있다.
- 그림: 데이터 탭에 원형 배치 SVG(현은 다른 상자를 지나지 않는다)와 문서 표. 라이브러리 없이 그린다.

## 결과

회사 문서 10개에서 참조 6, 주제 1, 데이터 20쌍. 전부 사람이 확인한 관계다:

| 인용 | 근거 |
|---|---|
| WH-004 → CS-002 | "보상 규정 적용 시" |
| WH-004 → OPS-010 | "주문 취소 규정에 따라 처리" |
| WH-009 → WH-004 | "재고 부족 처리 절차(WH-004)" |
| WH-009 → OPS-010 | "주문 취소 규정에 따라 처리" |
| OPS-010 → CS-002 | "보상 규정 CS-002 참조" |
| OPS-010 → CS-005 | "출고 후에는 반품 규정을 따른다" |
| SALES-006 → SALES-003 | 표 머리 "기본 할인" = 할인 승인 규정의 절 |

"배송 지연 보상 규정을 개정하면" 의 답: 주문 취소 규정(참조), 재고 부족 처리 절차(참조), 창고 운영 지침(재고 부족 처리 절차를 거쳐) + 같은 데이터: 주문 상태 정의(출고 예정일·지연 사유·운송사), 거래처 등급 기준(주문 금액), 월말 마감 절차(지연 사유·주문 금액). 비서 평가(`tasks_enterprise_docgraph.yaml` 5문항 × 3, 로컬 gpt-oss-20b): 첫 실행 80% → 도구 설명·프롬프트에 "인용·참조·개정 영향 질문은 search_docs 가 아니라 related_docs·impact_of" 를 적은 뒤 100%(15/15, 평균 2.3스텝). 실패 3건은 전부 모델이 검색으로 인용을 찾다가 놓친 경우였고 그래프 도구를 부른 실행은 전부 맞았다. 그래프 자체가 아니라 "언제 그 도구를 부를지" 가 문제였다.

## 한계와 다음

- 문자열 일치라 "앞 규정" 같은 대명사 인용은 못 잡고, 짧은 제목이 흔한 말이면(예: "운영 지침") 오탐이 날 수 있다. 10개 문서에서는 오탐 0. 문서가 수백 개가 되면 제목 별칭 규칙 대신 임베딩으로 인용 후보를 찾고 사람이 확정하는 방식이 맞다.
- 개념 사전은 사람이 쓴다. 자동화하려면 DB 열 주석(`schema.sql` 의 한국어 주석)에서 뽑는 방법이 있다.
- 회로 팩의 실험 추적 그래프(ADR-015)와 같은 "그래프 위의 도구" 패턴이지만 저장소는 다르다(그쪽은 SQLite 누적, 이쪽은 문서에서 매번 재계산 수 ms). 둘을 한 그래프 저장소로 합칠 이유는 아직 없다.
