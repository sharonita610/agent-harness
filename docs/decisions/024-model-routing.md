# ADR-024 모델 라우팅: 로컬로 돌리다 막히면 그 호출부터 강한 모델로

날짜: 2026-10-29 · 상태: 채택

## 배경

로컬 gpt-oss-20b 는 회사 팩 16문제에서 98~100%, 호스팅 gpt-5-mini 는 92%(되물음이 실패로 잡힘)에 48회 $0.19 였다(ADR-005, README 평가 절). 로컬이 싸고 빠르지만 회로 팩의 어려운 문제(분압기·인버터·소자 라이브러리의 Vf)에서는 스텝을 소진하거나 도구 오류를 반복한다. "항상 강한 모델" 은 비용과 지연을 전부 내고, "항상 로컬" 은 막힌 실행을 그냥 버린다. 질문을 미리 분류해 보내는 라우터는 분류기 자체를 또 평가해야 하고, 실제로 막히는 경우는 질문 종류보다 실행 중의 사고(인자 형식, 회로 실수)에서 온다.

## 결정

**실행 중 신호로 올린다.** 프로바이더 한 겹(`RoutingProvider`, `route:<싼 모델>-><강한 모델>`)이 대화 내용과 스텝 번호만 보고 호출마다 모델을 고른다. 분류기도, 학습도 없다.

| 신호 | 기준(기본값) | 올리는 시점 |
|---|---|---|
| 도구 오류 연속 | 직전 도구 결과가 연달아 2개 이상 오류("오류: …", "인자 검증 실패 …") | 다음 호출부터 |
| 스텝 소진 조짐 | 한 실행에서 6스텝을 넘겨도 답이 없음(루프가 `step` 을 넘겨준다) | 7스텝째부터 |
| 응답 품질 | 싼 모델의 응답이 비었거나(길이 제한) 도구 인자가 JSON 이 아님 | 같은 메시지로 즉시 강한 모델에 다시 묻는다(싼 모델의 토큰도 센다) |

한 번 올라가면 그 실행이 끝날 때까지 강한 모델이 맡는다(step 1 에서 초기화). 그래야 "강한 모델이 고쳐 놓으면 다시 싼 모델이 망치는" 왕복이 없다. 응답에는 실제로 답한 모델(`model`)과 올린 이유(`route`)가 붙고, 루프가 `llm` 이벤트와 토큰 집계(`usage.by_model`)에 그대로 남긴다. 평가 러너는 모델별 단가로 비용을 합치고 "강한 모델 호출 비율·올라간 실행 수·사유" 를 요약에 적는다.

다른 곳은 손대지 않았다. 서비스의 provider 허용 목록(`HARNESS_ALLOWED_PROVIDERS`)에 `route:…` 를 적으면 화면에서도 쓰고, 트레이스의 `llm.stepN` 스팬에 모델이 보인다.

## 결과

| 문제 묶음 | 로컬만 | 라우팅 | 올라간 실행 | 강한 모델 호출 | 비용 |
|---|---|---|---|---|---|
| 회사 16문제 × 3 | 98% | 100% (48/48) | 0/48 | 0/101 | $0 |
| 소자 라이브러리 4문제 × 3 | 83% (10/12) | 100% (12/12) | 4/12 | 16/54 (30%) | $0.05 |

회사 팩은 한 번도 안 올라갔다(로컬이 막히지 않으면 비용 0 으로 로컬과 같다). 라이브러리는 로컬이 틀리던 4개 실행이 올라가(스텝 초과 2, 도구 오류 연속 1, 빈 응답 1) 전부 맞혔고, 강한 모델은 호출의 30% 만 맡았다. 상세는 README 평가 절.

## 대안과 기각 이유

- **질문 분류 라우터(키워드·임베딩·소형 분류기).** 분류기의 정확도를 따로 측정해야 하고, 막히는 원인이 질문 종류가 아니라 실행 중 사고라 분류가 맞아도 못 잡는다. 신호 기반은 평가할 것이 "기준값 셋" 뿐이다.
- **실패한 실행을 통째로 강한 모델로 재실행(캐스케이드).** 단순하지만 싼 모델이 쓴 스텝과 지연을 전부 버린다. 호출 단위로 올리면 이미 모은 도구 결과(조회한 데이터, 시뮬레이션 결과)를 강한 모델이 이어받는다.
- **강한 모델을 판정자로 두고 싼 모델의 답을 검사.** 답이 틀렸는지 판정자도 모르는 경우(숫자 질문)가 많고 호출이 두 배가 된다.

## 한계

- 신호가 안 뜨는 틀린 답(싼 모델이 자신 있게 틀림)은 못 잡는다. 회사 팩의 되물음처럼 "틀리지 않았지만 통과도 아닌" 답도 그대로 간다.
- 기준값(오류 2, 스텝 6)은 두 팩의 경험값이다. 도구 호출이 많은 팩은 스텝 기준을 올려야 한다.
- 올라간 뒤 강한 모델이 받는 대화에는 싼 모델이 남긴 오류 흔적이 그대로 있다. 요약해서 넘기면 토큰이 줄겠지만 "무엇이 실패했는지" 가 강한 모델에게 유용한 정보이기도 해서 그대로 둔다.
