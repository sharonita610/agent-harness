# ADR-028 기록 가리기와 안전 마무리: README 의 약속과 코드의 예외를 없앤다

날짜: 2026-10-31 · 상태: 채택

## 배경

README 는 "안전장치는 프롬프트가 아니라 데이터 층에서" 라고 말하고, 기존 DB(HR)·에어갭 절까지 적어 두었다. 그런데 코드에 네 군데 예외가 있었다.
1. API 키를 쿼리 문자열(`?api_key=`)로도 받았다. 브라우저 기록·접근 로그·북마크에 키가 남는다.
2. 사람 채점 저장(`POST /grading/…`)에 인증이 없었다. "판정자가 사람과 95% 일치" 라는 숫자의 근거 파일을 아무나 덮어쓸 수 있었다.
3. 도구 결과 원문(4,000자)이 트레이스(JSONL)·서비스 DB(run_events)·평가 결과(JSON, 레포에 커밋)에 그대로 남았다. 비서는 답에서 마스킹해도 기록은 개인정보 저장소가 된다.
4. 결재 브로커가 처리된 전표의 이벤트·결정을 메모리에서 지우지 않았다.

## 결정

1. 키는 헤더(`Authorization: Bearer`, `x-api-key`)로만. 쿼리 문자열은 401. 화면·MCP·A2A 는 이미 헤더를 쓰고 `/files/` 는 공개 경로라 영향이 없다.
2. 채점 저장은 operator 이상. 저장 파일에 `graded_by` 를 적는다. 채점 페이지는 같은 출처의 localStorage 에 있는 화면 키(`harness.apiKey`)를 헤더로 보낸다.
3. **기록 가리기** `harness/observability/redact.py`. 두 층: 값의 꼴(휴대전화·유선전화·이메일·주민등록번호·카드번호 패턴)과 키 이름(phone·전화·연락처·email·주민·password·token·api_key 류는 값을 통째로). 적용 지점은 셋이다. 트레이스 수집기의 이벤트 데이터, 서비스가 저장하는 이벤트·답(화면으로 흘리는 실시간 스트림은 원문, 저장본만 가림), 평가 결과의 답·도구 호출(채점을 원문으로 끝낸 **뒤**). 기본 켬, `HARNESS_REDACT=0` 으로 끈다. 보존 기간 `HARNESS_TRACE_RETENTION_DAYS` 가 있으면 트레이스 파일을 쓸 때 오래된 것을 지운다.
4. 브로커는 처리된 전표를 1,000건까지만 들고, 넘으면 오래된 절반을 메모리에서 지운다(저장소에는 남는다). 대기 중 전표는 건드리지 않는다.

## 왜 채점 뒤에 가리나

"연락처를 답에 내지 않았는가" 는 함정 문제의 핵심 검사다. 저장 전에 가리면 모든 답이 통과해 버린다. 그래서 러너는 원문으로 채점하고 저장본만 가린다. 테스트가 "전화번호가 든 답은 실패로 채점되고 저장본에는 번호가 없다" 를 고정한다.

## 한계

- 패턴은 한국 형식 위주다(휴대전화 010, 주민등록번호 6-7). 다른 나라 형식은 패턴을 더해야 한다.
- 이름은 가리지 않는다. 이름만으로 개인을 특정하기 어렵고, 업무 기록에서 담당자 이름은 필요한 정보라서다. 필요하면 키 이름 힌트에 `name` 을 더하면 된다.
- 이미 저장된 과거 트레이스·결과는 소급 적용하지 않는다(가짜 데이터다).
