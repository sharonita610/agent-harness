# ADR-033 실데이터 적용 전 보정: 합성 데이터의 모양에 기대던 네 곳

날짜: 2026-11-02 · 상태: 채택

## 배경

네 팩의 평가는 합성 데이터에서 98~100% 다. 그 숫자를 받은 뒤 "이 코드에 실제 회사 데이터를 붙이면 어디가 먼저 깨지나" 를 전제로 코드를 다시 읽고, 의심되는 곳은 실측했다. 전부 로컬에서 합성 데이터와 손으로 만든 입력으로만 시험했다. 네 곳이 합성 데이터의 **모양**(띄어쓰기, 절 길이, 테이블 목록, 메모 내용)에 기대고 있었다.

| # | 어디 | 실측 | 왜 합성에서 안 드러났나 |
|---|---|---|---|
| ① | 기록 가리기 `observability/redact.py` | `"010-1234-5678로"`, `"900101-1234567입니다"`, `"1234-5678-9012-3456로"` 가 **그대로 남음**. 공백이 있으면 가려짐 | 시드의 메모는 번호 뒤에 공백·쉼표가 온다. 정규식 `\b` 는 한글을 단어 글자로 보므로 숫자와 조사 사이에 경계가 없다 |
| ② | SQL 가드 `tools/sql.py` | `SELECT id FROM orders WHERE note LIKE '%update%'` 가 "변경 키워드" 로 **거부** | 평가 질문이 메모 본문을 단어로 검색하지 않는다 |
| ③ | 규정 검색 `enterprise.search_docs` | 1,800자 절 5개 → 9,481자 → 루프의 4,000자 상한에서 **JSON 중간이 잘림**, 모델은 2개 남짓만 봄 | 합성 규정은 절이 최대 293자라 k=5 전문이 1,500자 안이다 |
| ④ | 데이터 범위 `enterprise/scope.py` | 범위 뷰는 6개 테이블 하드코딩, 그 밖은 **기본 허용**. 새 테이블은 범위 사용자에게 전부 보임 | 시드 스키마에 테이블이 9개뿐이고 늘어나지 않는다 |

(이 밖에 코드에서 읽은 전제는 결정 뒤 "남은 것" 에 적었다.)

## 결정

**① 가리기 경계를 영숫자 기준으로.** 패턴의 `\b` 를 `(?<![0-9A-Za-z])` / `(?![0-9A-Za-z])` 로 바꿨다. 한글 조사·서술어가 바로 붙어도 경계다. 이메일은 아이디·도메인을 영숫자로만 잡아 뒤의 조사("…com으로")는 남긴다. 계좌번호 패턴(3~6-2~6-4~8 자리) 과 키 힌트(`account_no`, `bank_account`, `iban`, `계좌`)를 더했다. 날짜(4-2-2), 실행 id(8-6), 수량 범위(3-3)는 묶음 수나 끝 묶음 길이가 달라 걸리지 않는다. 사업자등록번호(3-2-5)는 같은 꼴이라 함께 가려진다. **과가림 쪽을 택했다**: 기록은 디버깅용이고 개인정보 저장소가 되면 안 되는 쪽이 우선이다.

**② 가드는 문자열 리터럴을 비운 본문만 본다.** `'…'`, `"…"`(안의 `''`·`""` 이스케이프 포함)를 빈 리터럴로 바꾼 뒤 금지 키워드·세미콜론·스키마 명시를 검사하고, 실행은 원문으로 한다. 안전성 근거: 리터럴 안의 글자는 SQLite 도 데이터로만 읽고(`''' ; DELETE FROM orders; --'` 는 한 문자열), 진짜 방어는 읽기 전용 연결 + authorizer(②층)다. 닫히지 않은 따옴표는 리터럴로 치지 않아 그 뒤 키워드는 여전히 거부된다(보수적).

**③ 검색은 앞부분만, 전문은 `read_doc`.** 회로 팩이 이미 쓰던 꼴(`search_manual` 600자 + `read_manual`)을 회사 팩에 맞췄다. `search_docs` 는 절 앞부분(k 에 따라 600자 이하, k 개를 합쳐 3,600자 예산 안)과 `chars`, 잘렸으면 `…` 를 돌려주고 note 로 `read_doc(source)` 를 안내한다. `read_doc` 은 source('문서 > 절') 그대로, 절 제목, 문서 제목(전체)로 전문을 읽고, 결과에 `doc`·`section`·`source` 가 있어 출처 인용 채점(`extract_sources`, ADR-031)이 그대로 잡는다. 기본 k=5 의 미리보기는 580자라 합성 규정(≤293자)은 전과 같은 내용을 본다. k=10 이면 220자라 합성 규정도 잘리고 `read_doc` 한 스텝이 더 든다. **스텝 하나 ↔ 컨텍스트 상한 안에서 k 개를 전부 보는 것** 의 교환이고, 모델이 전문을 안 읽고 미리보기로 답할 위험은 인용 채점이 잡는다.

**④ 범위는 기본 거부.** `apply_scope` 가 `sqlite_master` 를 읽어 범위 뷰(`SCOPED_TABLES`)도 공용 참조 데이터(`SHARED_TABLES`: products·warehouses·inventory)도 아닌 테이블은 빈 임시 뷰(`WHERE 0`)로 덮는다. 나중에 붙은 테이블은 분류하기 전까지 범위 사용자에게 0행이다. 보이게 하려면 두 목록 중 하나에 적는다. 빈 뷰(조용히 0행) 대신 오류를 내는 쪽도 생각했지만 SQLite 뷰로는 할 수 없고, "범위 밖은 없는 것처럼 보인다" 가 기존 범위 뷰의 의미와도 같다.

## 결과

- 테스트 6건 추가(가리기 1, 가드 3, 검색 1, 범위 1). 전체 246개 통과, ruff 통과, MCP 점검 통과.
- 같은 평가를 다시 돌렸다(로컬 gpt-oss-20b, llama.cpp, 회사 16문제 n=1, `--tag adr033`): **15/16(93.8%)**, 평균 2.1스텝, p50 7.5초, 출처 정확도 100%(인용한 절이 전부 그 실행에서 검색된 절). 실패 1건(m01)은 모델이 "지난달" 을 주문일 대신 출고 예정일(`shipments.planned_date`)로 세어 6건(정답 5건)이라 답한 것이고, 검색 도구를 부르기 전 단계라 이번 변경과 무관하다. m01 만 n=3 으로 다시 돌리니 3/3 통과(`--tag adr033-m01`). `read_doc` 은 16문제 중 t01 에서 1회 호출됐고 나머지는 580자 미리보기로 충분했다. 결과: [`20261102-005014_local_adr033.json`](../../harness/evals/results/20261102-005014_local_adr033.json) · [`20261102-005335_local_adr033-m01.json`](../../harness/evals/results/20261102-005335_local_adr033-m01.json).
- ①②④는 평가 질문이 건드리지 않는 경로라 결과 숫자에 영향이 없다. 도구 목록에 `read_doc` 이 하나 늘었다(회사 팩 13개).
- 네 커밋: ① `8a05d9b` ② `50efb59` ④ `cc4704e` ③ `e12dd58`. 각각 되돌릴 수 있다.

## 한계

- ①: 이름·주소는 여전히 가리지 않는다(ADR-028 의 판단 그대로: 업무 기록에 담당자 이름은 필요하다). 가리기는 저장본에만 적용되고 화면 스트림은 원문이다(설계). 패턴은 한국 형식 위주다.
- ②: 주석(`--`, `/* */`) 안의 키워드는 여전히 거부된다. 드물어서 두었다.
- ③: `DocIndex`(마크다운, 메모리) 에만 `get_section` 을 더했다. `KnowledgeBase`(PDF, SQLite) 는 이미 있었다. 미리보기 글자 수는 글자 기준이라 루프의 상한(글자)과 같은 단위다.
- ④: 범위 사용자는 숨긴 테이블을 "없다" 와 구분하지 못한다. `scope_note` 에 숨긴 테이블 이름을 알려 주는 것은 다음. 공정 팩은 범위 기능이 없다.

## 남은 것(코드에서 읽었지만 이번에 고치지 않은 전제)

- **오늘 날짜가 고정**(`REFERENCE_DATE`, 시드 날짜). 프롬프트가 "오늘은 2026-10-xx" 라고 알리고 `date('now')` 를 금지한다. 평가 문제도 "지난달(2026년 9월)" 처럼 날짜가 박혀 있다. 실데이터는 스냅샷 시각을 주입하고 평가 문제를 상대 날짜로 바꿔야 한다. → ADR-034 에서 고쳤다.
- **마스킹 열이 `phone` 하나**(`MASK_COLUMNS`). 실 스키마의 `contact`·`manager_tel`·`email`·`address` 는 열 이름으로 안 가려진다. 민감도 등급표 → 열 허용 목록이 먼저다(README "기존 DB 를 붙일 때"). → ADR-035 에서 고쳤다(뷰 단계 마스킹, 별칭 우회도 함께).
- **마크다운 청킹은 `## ` 한 단계**. 제목 없는 문서는 문서 하나가 청크 하나다. PDF 청킹은 책갈피 있는 매뉴얼 전용 상수(`HEADER_Y/FOOTER_Y`)를 쓴다.
- **판정자·라우팅은 데이터를 밖으로 보낼 수 있다**(`harness judge` 는 답변 원문을, `route:` 는 올라간 뒤 대화 전체를). 오프라인 모드(ADR-027)가 막지만 켜지 않은 인스턴스에서는 유출 경로다.
- **결재 대기 600초·메모리, 동시성 1, 공정 팩 이미지 분류는 모의**. 실제 결재 리듬·사용자 수·분류기 연결은 제품의 일이다.
- 선택지와 교환은 README "기존 DB 를 붙일 때" 의 트레이드오프 표에 있다.
